# Codex static contracts

Run `node --test evals/codex/contracts.test.cjs` (also exposed by `npm run test:codex`). Node.js 18 or later; no dependencies.

These are **static instruction and package checks**, not model-backed orchestration tests. The package test checks file availability from an unrelated working directory and rejects an incomplete package; it does not execute the adapter.

| Criteria | Checks |
|---|---|
| CX-002 | All routes, explicit-only metadata, package completeness, source/project paths, declared tool schema, isolation, lifecycle and reviewer nonmutation instructions |
| CX-003 | SHA-256 of the original fourteen Claude skill bodies/frontmatter after removing only one bounded Codex entry; unchanged agent definitions, manifests, continuity and Claude model runners |
| CX-004 | Canonical debate and Evidence ownership, limits, combined PRD/catalogue gate, unaffected adversarial cases and retained material-restart expectations |
| CX-005–CX-011 | v2.0.0 review-contract invariants: `Context:` field on all 12 agents; `Self-check:`/`Sweep:` scoped to the right agents and absent from adversarial-reviewer; the `RV-<scope>-NNN` finding schema, its three classes, and the late-finding rationale rule on code-reviewer/doc-reviewer; adversarial-reviewer's explicit `CH-*`/non-RV-ID statement; the three coordinator skills carrying the Required-reading rule, Context gate, and RV-ID contract byte-identically outside frontmatter/Stack Profile; the four document agents' Step 0 `Glob('docs/**/*.md')` inventory; and the `review-contract` skill package's existence with its three reference files |

`baseline.json` was originally anchored to commit `13f7469a171505f4a4a378d1f56356f487c212ee`, captured before this change, and stayed anchored there through v1.9.0. For v2.0.0 it was re-anchored twice against the uncommitted working tree — once for the initial review-contract rollout (subtasks S1–S6) and again for the second round of fixes described below — see the re-anchor record. Only CRLF/LF normalization is permitted in either case. The standing rule is unchanged: the baseline is deliberately independent of the current Git HEAD and must not be regenerated just to pass a test — a re-anchor is a deliberate, recorded act tied to a described change set, never a silent drive-by fix. Intentional future changes to the common workflow require separate review of the corresponding preservation baseline.

### Re-anchor record — v2.0.0 review-contract change (2026-09-15)

`baseline.json`'s `shared` and `preserved` hashes were regenerated from the working tree for `agents/*.md` (all 12), the three coordinator skills (`dev-team`, `dev-team-node`, `dev-team-python`), the eleven `ask-*` shared skills, `skills/handoff/SKILL.md`, `skills/resume/SKILL.md`, and the three plugin manifests (`.claude-plugin/plugin.json`, `.codex-plugin/plugin.json`, `.copilot-plugin/plugin.json`). This is an intentional re-anchor, not a drive-by fix, and it now covers two rounds of change: subtasks S1–S6 landed the v2.0.0 review-contract change (new `Context:`/`Self-check:`/`Sweep:` report fields, the `RV-<scope>-NNN` finding schema with `must-fix-now`/`fix-in-slice`/`backlog` classes and its late-finding rule, the coordinators' Required-reading + Context gate, the document agents' Step 0 documentation inventory, and the new `skills/review-contract/` skill), and a second round of five fix subtasks then repaired 33 defects the two reviewers found in that rollout — across agent prompts, coordinator skills, `ask-*` shortcuts, `specs/workflow.md`, and documentation. This record reflects the final state after both rounds, so the prior baseline (captured before either round, at commit `13f7469a171505f4a4a378d1f56356f487c212ee`) no longer describes any of these files. Every regenerated hash was produced by the exact `read`/`hash` pipeline `contracts.test.cjs` uses (`fs.readFileSync(..., 'utf8').replace(/\r\n/g, '\n')` then SHA-256; the `shared` entries additionally strip the bounded `<!-- codex-entry:start -->...<!-- codex-entry:end -->\n\n` block before hashing, exactly as `CX-003` does) — no other normalization was applied. Files not touched by either round (`.claude-plugin/plugin.json`, `.codex-plugin/plugin.json`, `agents/adversarial-reviewer.md`, `evals/runner/run-tier2.sh`, `evals/runner/run-tier3.sh`, `.claude-plugin/marketplace.json`) kept their prior hash unchanged, confirming the regeneration only moved for files that actually changed. `.copilot-plugin/plugin.json` is a plugin manifest like the other two and is now hashed under `preserved` for the same reason — it changed (a version bump) alongside them but had no baseline entry before this re-anchor, leaving it unprotected by the preservation contract; that gap is closed here.

The `commit` field is deliberately set to the placeholder `uncommitted-worktree — re-anchor pending the v2.0.0 commit` because this re-anchor was produced against an uncommitted working tree — committing the v2.0.0 change set is the user's decision, not an agent's. **Once the commit that lands v2.0.0 is made, `commit` must be updated to that commit's SHA** (mirroring how the prior baseline recorded `13f7469a171505f4a4a378d1f56356f487c212ee`); until then, this field is a marker, not a Git reference.

`CX-004`'s ordinary-review token for `skills/ask-prd/SKILL.md` and `skills/ask-planner/SKILL.md` was updated for v2.0.0 from `'maximum 2 ordinary reworks'` to `'2-round rework budget'`. The rule the token guards did not weaken — a bounded ordinary-review budget separate from the `CH-*` debate budget is still asserted — but its wording changed everywhere in the v2.0.0 change set (`CLAUDE.md`, the three coordinator skills, and all eleven `ask-*` skills) because the budget is now counted on open `must-fix-now` findings rather than on raw rework dispatches. `contracts.test.cjs` is not itself hashed in `baseline.json` (it is neither a `shared` nor a `preserved` entry), so this token update needed no baseline re-anchor.

The single allowed routing insertion is delimited by `<!-- codex-entry:start -->` and `<!-- codex-entry:end -->`, followed by one blank line. The original content outside that insertion must remain unchanged.

Not covered here: actual natural-language activation, tool execution in different Codex clients, inherited history, successful review/rework, model compliance with read-only constraints, live interruption/resume, installed-cache loading, and Claude behavioral parity. These require separately recorded live runs; static green leaves them UNVERIFIED.

Also not covered: a tier-1 eval case for `review-contract` skill surfacing. The tier-1 runner only evaluates skills carrying a `promptSignals` frontmatter block; `review-contract` is invoked by name from agent prompts rather than surfaced from user phrasing, so adding that metadata purely to satisfy a test was rejected deliberately.
